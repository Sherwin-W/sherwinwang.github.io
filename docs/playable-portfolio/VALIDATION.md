## Limits and outstanding checks

- Eight warm exact/alias submissions measured 32.1 ms p95 from Enter keydown to the second animation frame after the object entered the DOM (Chromium desktop, 1440x900). For recognition, the worker round-trip timer begins after rasterization and Worker construction; it must not be read as activation-to-visible or cold-start latency. The 12 browser fixtures measured 51.9–80.3 ms from Recognize activation to visible suggestions in Chromium using Vite locally at a 390x844 viewport on a desktop machine, not a phone. The first test request reported 35.9 ms worker round-trip and 1.5 ms inference; 306,484 model bytes. A separately simulated request path delayed manifest/weights by 80/180 ms and measured 380.5 ms activation-to-visible (313.7 ms worker round-trip). This is an artificial local route-delay test, not a public-network measurement. Detailed values are recorded in `browser-fixture-results.json` and `RECOGNITION.md`.
- Browser verification covers outside release, pointer cancellation, resize clamping and keyboard deletion. The 30-object code cap has unit coverage, but 30-object performance has not been measured.
- Recognition is experimental: per-class held-out top-1 ranges from 49.3% to 76.5%. The `other` rejection output has been measured on only eight named negative categories; arbitrary unsupported drawings can still be mislabeled. Displayed scores are uncalibrated model outputs. Browser-drawn examples are integration checks, not a human-drawn benchmark. See `RECOGNITION.md`.
- Project architecture diagrams, verified project links, detailed technology facts, and a resume are unavailable in the repository content inspected. The old Contact LinkedIn href was a placeholder; a separate About handle is unverified. See `CONTENT_GAPS.md`. No fabricated architecture or URLs are shown.
